# PRIMER_KVM — устройство платы

Описание аппаратной части (FPGA) и прошивки ядра. Сборка и подключение — в [README](../../README.md).

## 1. Структура

```
config/project.cfg        конфигурация: пути к инструментам, частоты, видео, сеть
scripts/                  PowerShell (UTF-8 с BOM - PowerShell 5.1 иначе искажает кириллицу)
  setup.ps1               установка и проверка инструментов
  build.ps1               полная сборка: fw-build -> ip-gen -> synth -> merge
  gen-config.ps1          project.cfg -> fpga/rtl/kvm_config_pkg.sv, firmware/include/kvm_config.h, edid_data.h
  fw-build.ps1            прошивка ядра (CMake + Ninja + RISC-V GCC) -> firmware/build
  ip-gen.ps1              IP Gowin (копии из IDE + файлы настроек) -> fpga/ip; временные ограничения kvm.sdc
  synth.ps1               синтез и размещение (gw_sh), проверка таймингов
  merge.ps1               прошивка ядра в битстрим (merge_bit) -> fpga/impl/pnr/PRIMER_KVM_fw.fs
  flash.ps1               запись битстрима во flash платы (programmer_cli)
  pc-net-setup.ps1        статический адрес сетевого адаптера ПК
  usbdesc.py              генератор fpga/rtl/usb_desc_rom.sv (описатели USB)
fpga/rtl/                 SystemVerilog
fpga/constraints/         kvm.cst (выводы, места PLL), kvm.sdc (генерирует ip-gen.ps1)
fpga/process_config.json  настройки проекта Gowin (менять здесь, а не в IDE)
fpga/ip/, fpga/impl/      создаются при сборке
firmware/app/             прошивка ядра PicoRV32
firmware/sdk/             файлы SDK Gowin_PicoRV32 (config.h: BUILD_LOAD; picorv32.h: SYSCLKFREQ = CPU_CLK_HZ)
tools/                    make_hex и merge_bit из SDK Gowin_PicoRV32, xPack RISC-V GCC (ставит setup.ps1)
```

Файл проекта `fpga/PRIMER_KVM.gprj` создаёт `synth.ps1`: в него попадают все `.v/.sv` из `fpga/rtl` и
`fpga/ip` — новый модуль достаточно положить в папку. Проект можно открыть в Gowin IDE после сборки, но
настройки и список файлов при следующей сборке перезаписываются.

## 2. Конфигурация

`config/project.cfg`, формат `КЛЮЧ=значение`. Числа, IP, MAC и строки в кавычках `gen-config.ps1` экспортирует в
`kvm_config_pkg` (RTL) и `kvm_config.h` (C). Сетевые адреса используются и в прошивке, и в RTL — после
изменения нужна полная сборка.

| Ключ | По умолчанию | Назначение |
|---|---|---|
| GOWIN_BIN, GOWIN_PROGRAMMER_BIN | `C:\Gowin\Gowin_V1.9.11.03_Education_x64\…` | gw_sh, programmer_cli; исходники IP — `GOWIN_BIN\..\ipcore` |
| RISCV_DIR, RISCV_PREFIX | `tools\xpack-riscv`, `riscv-none-elf-` | компилятор прошивки |
| PICORV32_SDK_DIR, PICORV32_SDK_ZIP | `tools\gowin_picorv32`, архив SDK | make_hex, merge_bit |
| TIMING_MARGIN_PCT | 15 | обязательный запас по частоте каждого такта |
| CPU_CLK_HZ | 40 500 000 | такт ядра и шины Wishbone |
| VIDEO_* | 1280×720@60, 74.25 МГц | режим EDID, размер буфера кадра (ширина кратна 32) |
| HDMI_PHASE, HDMI_CHn_IODELAY | auto, 0 | фаза выборки IP DVI RX (0…15) и задержка входа канала (0…127, ~18 пс) |
| DDR_MEM_CLK_HZ | 310 500 000 | такт памяти DDR3 (стандарт требует ≥ 303 МГц) |
| NET_IP_ADDR, NET_MAC_ADDR, NET_UDP_PORT | 192.168.50.10, 02:4B:56:4D:00:01, 50000 | сеть платы |
| NET_PC_ADAPTER, NET_PC_IP_ADDR | `Realtek USB GbE*`, 192.168.50.1 | адаптер ПК для pc-net-setup.ps1 |

## 3. Такты и временные ограничения

| Такт | Частота | Источник |
|---|---|---|
| clk_sys | 40.5 МГц | rPLL 27 / 2 × 3 (ядро, Wishbone, Ethernet-регистры) |
| ddr_mem / ddr_clk | 310.5 / 77.625 МГц | rPLL 27 / 2 × 23; IP DDR3 делит на 4 (логика DDR3, видео) |
| tmds_clk / pix_clk | 74.25 МГц | вход HDMI; IP DVI RX (rPLL ×5, IDES10) |
| eth_ref / eth_mii | 50 / 25 МГц | RTL8201F; делитель в IP MII to RMII |
| usb_clk | 60 МГц | CLKOUT USB3317 (ULPI) |

- Периоды в `kvm.sdc` — настоящие, делённые на 1 + TIMING_MARGIN_PCT/100: сборка без нарушений означает запас
  не меньше 15% по моделям Gowin. При любом нарушении `synth.ps1` завершается ошибкой; запас сверх
  обязательного меньше 2% — предупреждение.
- Выводы ULPI ограничены по табл. 4.3 USB3317 (запас в наносекундах: setup 1 нс, hold 0.5 нс). CLKOUT приходит
  к сети такта через общую трассировку (вывод T15 не тактовый), поэтому все входы ULPI идут через IODELAY
  (`ulpi_io.sv`).
- Места трёх PLL закреплены в `kvm.cst` (`INS_LOC`): иначе размещение от сборки к сборке разное, и от него
  зависит калибровка DDR3.
- В домене pix_clk сравнения и арифметика считаются на такт раньше, в регистрах.
- Умножение и `$clog2` внутри выражений синтез Gowin считает неверно: `$clog2` — только в параметрах и ширинах,
  умножение — сдвигами и сложениями.

## 4. IP (`ip-gen.ps1`)

Консольный генератор IP в Gowin V1.9.11.03 не работает, поэтому IP готовятся скриптом: исходники копируются из
`IDE\ipcore`, файлы настроек пишутся по шаблонам генератора.

| IP | Папка | Настройки |
|---|---|---|
| rPLL ядра и DDR3 | `pll_sys`, `pll_ddr` | делители подбираются точно: PFD 3…500 МГц, VCO 500…1250 МГц (UG286 §5.1) |
| Gowin_PicoRV32 | `gowin_picorv32` | `pico_define.vh`: RV32IMC, ITCM 32 КБ, DTCM 8 КБ, WB UART, WB GPIO, Open Wishbone; в `picosoc.v` задержка сброса переведена на передний фронт (иначе путь в полпериода) |
| TSE MAC + MII to RMII | `eth_mac`, `eth_m2r` | MII, `eth_mac_all.v` |
| DDR3 Memory Interface | `ddr3` | 1:4, контроллер + PHY, CL 6 / CWL 5, tCK из DDR_MEM_CLK_HZ, ODT 60 Ом |
| DVI RX | `dvi_rx` | rPLL ×5, фаза и задержки из project.cfg, `dvi_rx_all.v` |
| USB 2.0 Device Controller | `usb_dev` | ULPI, High Speed, EP1/EP2 IN — interrupt, `usb_dev_all.v` |

Макрос `module_name` общий у всех IP Gowin: каждый шифрованный файл компилируется только через свою обёртку
`*_all.v`, которая подключает его вместе с настройками.

## 5. Прошивка ядра

- Компилятор xPack GNU RISC-V Embedded GCC, `-march=rv32imc_zicsr -mabi=ilp32 -Os`, без стандартной библиотеки.
- Линкер (`linker/kvm.ld.in`): код и константы — ITCM 0x0200_0000, данные — DTCM 0x0100_0000, стек — с конца
  DTCM (не меньше 1 КБ). Начальное содержимое ITCM — `ram32.hex` (make_hex) при синтезе и `merge_bit` при склейке.
- Главный цикл: приём Ethernet, вывод UART из очереди (`sys.c`), раз в 10 мс — PHY, DDR3, HDMI, видео, USB, LED.

| Файл | Назначение |
|---|---|
| main.c | запуск, главный цикл, протокол KVM |
| net.c, eth.c, mdio.c | ARP, IPv4, ICMP echo, UDP; буферы кадров; MDIO |
| ddr.c | ожидание калибровки и проверка DDR3 |
| hdmi.c | EDID, HPD, включение захвата |
| video.c | буферы кадра, тестовая картинка, обновления из плиток |
| usb.c | отчёты клавиатуры и мыши |
| kvm_regs.h, kvm_proto.h, board.h | регистры периферии, протокол с ПК, биты GPIO |

**UART** (COM-порт BL702, 115200 8N1): сводка при запуске (прошивка, сеть, DDR3, EDID), события (сигнал HDMI,
приложение подключено/отключено, USB, режим управления) и ошибки.

**Светодиоды:** LED0 — мигает 1 Гц; LED1 — идёт захват HDMI; LED2 — DDR3 исправна; LED3 — передаётся видео;
LED4 — принимаются кадры Ethernet; LED5 — приложение на связи.

Битстрим с прошивкой хранится во внешней SPI-flash (XT25B32, 4 МБ) с адреса 0, занимает ≈0.9 МБ.

## 6. Карта адресов ядра

| Адрес | Назначение |
|---|---|
| 0x0100_0000 | DTCM 8 КБ |
| 0x0200_0000 | ITCM 32 КБ |
| 0x1100_0000 / 0x1100_1000 | WB UART / WB GPIO |
| 0x2000_0000 | слот 0: `hdmi_rx` (EDID — 0x100…0x1FF) |
| 0x2000_1000 | слот 1: `eth_sys` (буферы кадров — 0x800…0xFFF) |
| 0x2000_2000 | слот 2: `video_tx` |
| 0x2000_3000 | слот 3: `ddr_arb` (состояние DDR3) |
| 0x2000_4000 | слот 4: `usb_hid` |
| 0x3000_0000 | DDR3, 128 МБ |

Дешифратор (`wb_mux.sv`) смотрит только adr[28] и adr[15:12]; пустой слот читается как 0. Регистры каждого
модуля описаны в его заголовке и в `firmware/app/kvm_regs.h`.

## 7. Выводы

| Сигнал | Вывод | Примечание |
|---|---|---|
| clk_27m, key0_n (K0) | H11, T10 | генератор; общий сброс (T10 — вывод SSPI, разрешён как обычный) |
| uart_tx / uart_rx | M11 / T13 | BL702 |
| LED0…LED5 | C13, A13, N16, N14, L14, L16 | 0 — горит; C13/A13 — DONE/READY как GPIO |
| tmds_clk, tmds_d[0..2] | C12/B12, B13/A14, B14/A15, D14/E15 | модуль PMOD_DVI в J6; у пар данных P на выводе [B] — данные инвертируются в `hdmi_rx` |
| hdmi_scl / sda / hpd | A11 / N6 / N9 | DDC и HPD модуля проводами в J5 |
| RMII | A9 (REF_CLK), C9/F15, M6, L8, E14/D16, E16 | RTL8201F |
| eth_rst_n | F10 | общий сброс RTL8201F и USB3317 |
| eth_mdc / eth_mdio | F14 / F16 | общие с DDC разъёма HDMI Dock через 2N7002 |
| ULPI | T15 (CLKOUT), K12, K13, K11, G11, H12, J12, H13, T14, R13, P13, R12 | USB3317, SW2 — DEVICE |
| ddr_* | см. `kvm.cst` | DDR3 на модуле |

Кнопки K1…K3 и DIP-переключатели недоступны: их выводы — половины пар IO, занятых DDR3.

## 8. Сеть и протокол

Плата подключается к ПК напрямую: плата 192.168.50.10, ПК 192.168.50.1/24 (`pc-net-setup.ps1`). Приложение
привязывает сокет к адресу ПК из подсети платы, поэтому работает и при включённом VPN.

`eth_sys.sv`: RTL8201F (RMII) ↔ MII to RMII ↔ TSE MAC (MII) ↔ буферы в BSRAM: приём — 2 кадра по 2 КБ,
передача — кадр ядра и 2 буфера видео. PHY: через MDIO включается RMSR бит 2 (`Rg_rmii_rxdv_sel`, даташит
RTL8201F §7.16), иначе CRS_DV в конце кадра даёт ошибку каждого кадра.

Протокол — UDP, порт 50000, little-endian (`firmware/app/kvm_proto.h`). Заголовок 8 байт: magic «KVM1», cmd,
flags, seq; ответ — `cmd | 0x80` с тем же seq.

| cmd | Запрос | Ответ |
|---|---|---|
| 0x01 STATUS | — | `kvm_status_t`, 76 байт: время работы, счётчики Ethernet, прошивка, DDR3, HDMI, USB |
| 0x02 ECHO | данные | те же данные |
| 0x04 UPDATE | flags бит 0 FULL — все плитки | `kvm_update_t`, 20 байт: результат, источник, номер обновления, число плиток, размеры |
| 0x05 INPUT | `kvm_input_t`, 16 байт: клавиши (коды HID), кнопки и координаты мыши, счётчики колеса | нет |

Обновление — пакеты плиток 32×16 «KVT1» (заголовок 22 байта + 1024 байта RGB565, всего 1088 байт) на адрес
отправителя запроса. Без FULL передаются только плитки, изменившиеся с прошлого обновления. Полное обновление
1280×720 — 1800 пакетов, ≈0.16 с при 100 Мбит/с.

## 9. DDR3 и видео

- H5TQ1G63EFR, 128 МБ. `ddr_arb.sv`: порт записи захвата (высший приоритет), окно памяти ядра (запись
  отложенная, чтение ~0.5 мкс), порт чтения видео. При старте `ddr.c` проверяет адресные линии, запись байтами
  и 256 КБ данных.
- **Захват HDMI** (`hdmi_rx.sv`): IP DVI RX → RGB565 → асинхронная FIFO → DDR3. Кадр выделяется по DE. Три
  буфера: захват пишет в свободный, передача закрепляет последний полный кадр — разрывов и неполных кадров нет.
  Во время захвата считается CRC-32 каждой плитки 32×16; таблица сумм пишется за кадром.
- **EDID** (E-EDID 1.3, один режим из project.cfg) отдаёт `i2c_edid.sv` (адрес 0x50).
- **Передача** (`video.c`, `video_tx.sv`): прошивка сравнивает суммы плиток с тем, что уже есть у ПК, пишет
  список плиток в `video_tx` и запускает передачу; `video_tx` читает плитки из DDR3 и собирает пакеты в буферы
  `eth_sys`. Пока нет сигнала HDMI, передаётся тестовая картинка (буфер 3).
- Буферы: 0…2 МБ, 2…4, 4…6 — захват; 6…8 — тестовая картинка; с 8 МБ — суммы плиток, которые есть у ПК.

## 10. USB: клавиатура и мышь

- USB3317 (ULPI) на Dock, разъём USB-C — к удалённому ПК. **VBUS разъёма соединён с +5 В платы:** при питании
  платы от своего источника подключать удалённый ПК кабелем без линии питания.
- Gowin USB 2.0 Device Controller, High Speed. Составное устройство: IF0 — клавиатура с поддержкой BIOS (EP1 IN,
  8 байт), IF1 — мышь с абсолютными координатами (EP2 IN, 7 байт: 5 кнопок, X/Y 0…32767, колесо, горизонтальная
  прокрутка), опрос 1 мс. Описатели генерирует `scripts/usbdesc.py`; VID/PID 1209:0001 — тестовый
  идентификатор pid.codes.
- Описатель отчётов HID выбирается по wIndex запроса GET_DESCRIPTOR; запросы класса HID обслуживает `usb_hid.sv`.
- Ядро USB держится в сбросе, пока USB3317 в сбросе, и ещё 3 мс после появления CLKOUT.
- `usb.c`: отчёт отправляется при изменении состояния из пакета INPUT; нет пакетов 0.5 с — все клавиши и
  кнопки отпускаются.

## 11. Расширение

- Новый модуль FPGA — файл в `fpga/rtl`, подключение в `kvm_top`.
- Новый параметр — строка в `project.cfg`; в RTL — `kvm_config_pkg::ИМЯ`, в C — `ИМЯ` из `kvm_config.h`.
- Своя периферия ядра — свободный слот `wb_mux` (параметр `NSLOT` в `kvm_top`, 4 КБ на слот).
- Ещё один потребитель DDR3 — порт в `ddr_arb.sv` (домен ddr_clk).
- Новый такт — в разделе SDC `ip-gen.ps1` и в `set_clock_groups`.
